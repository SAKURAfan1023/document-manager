# Dev Flow 任务记录：df-20260811-105740-42da79

## 任务概览

### 原始目标

在文档预览页最右侧增加绝对定位的可展开栏，以列表展示按打开时间倒序排列的 HTML、Markdown 文件，并提供美观、易懂的快速切换入口。

### 最终交付

在全局 Reader 工作区右侧新增绝对定位的“最近打开”展开栏。各分屏真实打开 HTML/Markdown 时更新记录，列表按最后打开时间倒序展示并持久化到 localStorage；点击条目复用现有主分屏切换和未保存确认流程。根据用户两轮截图反馈，页签最终位于列表左侧，二者组成同一刚性容器同步左右推拉；折叠时容器整体右移并只留下页签，展开时页签带动列表同步左移。

## 人在回路

### 用户提供的信息

- 现有预览页缺少最近打开文件的快速回访入口。
- 展开栏应位于预览页最右侧，使用绝对定位，不挤压正文；列表只覆盖 HTML、Markdown，并按打开时间排序。

### 需求澄清与决策

| 时间/轮次 | 类型 | 用户信息或纠正 | 当前归并结论 | 状态与影响 |

| 2026-08-11 首轮 | 原始需求 | 右侧增加绝对定位展开栏，按打开时间显示 HTML、MD | 实现可收起的最近打开栏，记录持久化并可点击切换文件 | 功能需求仍有效 |
| 2026-08-11 反馈轮次 | 视觉纠正 | 应是一个整体，类似书本页签，左右过渡式推拉 | 面板与页签必须无缝连接、共享整体视觉；收起只留页签，内容横向推入推出 | 当前有效，替代两个独立浮层的视觉方案 |
| 2026-08-11 二次反馈 | 结构纠正 | 页签在列表左侧，页签与列表必须相连并同步外移 | 页签与列表按左、右顺序进入同一 flex 容器；只允许整体容器承担横向位移 | 当前有效，替代固定页签、列表单独滑动的方案 |

### 方案演进

- 采用现有阅读器状态和 LibraryItem 数据，不新增后端接口或数据表；最近打开记录保存在 localStorage，渲染时与当前文件索引交叉过滤。
- 列表保存每个文件的最后打开时间，同一路径重复打开时更新并置顶；未打开文件不进入列表。
- 初版用间距、独立圆角和独立阴影呈现面板与触发器，被用户纠正为书本页签式整体；第一次修正仍让页签固定、列表单独滑动，第二次修正将页签移到列表左侧，并把唯一的横向 transform 提升到共同父容器。

### 当前有效需求基线

- 目标结果：预览页右侧拥有书本页签式、一体化、可横向推拉的 HTML/Markdown 最近打开列表，支持快速切换。
- 范围：my.document 前端阅读器、浏览器本地打开历史及相关样式。
- 非目标：不新增后端历史接口，不记录 PDF/图片/文本，不改变多窗口、编辑保存或文件树行为。
- 验收条件：右侧栏不占正文布局；展开时页签位于列表左侧且二者无间隙、无分离阴影；页签与列表作为整体同步移动，收起时整体右移只露页签，展开时整体左移；仅显示已打开的 HTML/Markdown；按最近打开倒序；点击条目打开文件；刷新后记录保留；删除或已不存在的条目不显示；空态易懂。
- 兼容与发布约束：只修改现有 React/CSS；保留上一轮尚未提交的 Markdown 预览适配；按仓库指令不执行前端构建或浏览器验证。
- 外部操作授权：仅允许本地代码和项目内 Dev Flow 记录修改，不提交、不推送、不发布。
